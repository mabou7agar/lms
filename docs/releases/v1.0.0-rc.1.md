# HELBARON LMS — Release Candidate 1.0.0-rc.1

Status: **Release Candidate — not yet production-authorized.** The final `v1.0.0`
tag is created only after the on-machine gates in `docs/verification/w09/` (container
smoke, Playwright/axe, image Trivy re-scan) pass and the release is explicitly
authorized.

## Summary
First production release candidate of the bilingual (EN / AR, RTL) MENA LMS: catalog,
enrollment and learning, authoring, assessment, assignments, certification, commerce,
subscriptions, CRM, notifications and analytics. Backend: Laravel 12 (PHP 8.4,
PostgreSQL 16, Redis). Frontend: Next.js 15 (React 19, TypeScript strict).

## Migration summary
**No schema changes in this candidate.** W09 is a code-only advance over W08 (`9419bc6`):
the two release-blocking fixes are an application-level checkout lock and a frontend
path correction — neither alters the database. `php artisan migrate` is a no-op relative
to a W08 deployment. A fresh install applies the full schema via `migrate --seed`
(148 tables verified).

## What changed since W08
- Fixed the web client `/api/v1/v1/...` double-prefix that 404'd the authoring, media,
  grading and lesson-player surfaces (see CHANGELOG).
- Fixed checkout double-charge on duplicate submit via a per-user distributed lock.
- Version set to `1.0.0-rc.1`.

## Upgrade instructions (from a W08 deployment)
1. Deploy the new images (built from this commit — see the deployment manifest).
2. Run `php artisan migrate --force` (no-op here, kept for pipeline uniformity).
3. Run `php artisan config:cache` and warm caches; restart php-fpm, Horizon, scheduler.
4. No data backfill required.

## Rollback instructions
Because there are no schema changes, rollback is a pure image swap:
1. Re-deploy the previous images (the W08 `helbaron-api` / `helbaron-web` digests).
2. Restart php-fpm, Horizon and the scheduler.
3. No database rollback is required (no migrations were applied).
If a database restore is ever needed, use `scripts/db-restore.sh <dump> --force`
against a disposable target first (drill verified: 148 = 148 tables, checksum OK),
then promote. Keep the pre-deploy `pg_dump` (`scripts/db-backup.sh`) as the restore point.

## Known limitations (this candidate)
- Container health smoke, the Playwright browser matrix (Chromium desktop + mobile,
  EN LTR + AR RTL), axe accessibility, and image Trivy re-scans are **validated only on
  a Docker-capable host** — they are consolidated into
  `docs/verification/w09/W09_WINDOWS_UAT.ps1` and must be run there before the final tag.
- The production stack refuses to boot on placeholder secrets by design (W08 boot guard);
  a real `apps/api/.env.production` is required for any live run.
- Pest's `--parallel` runner throws ~11 spurious failures from cross-worker DB isolation;
  the authoritative sequential run is green (823 passed). CI should run Pest sequentially
  (or with isolated per-worker databases) until parallel isolation is hardened.
- Advisory (non-blocking) performance items are catalogued in
  `docs/verification/w09/UAT_MATRIX.md` (a few reverse-lookup indexes; catalog search
  uses a leading-wildcard ILIKE that would benefit from pg_trgm at scale).
