# Release Notes — v1.0.0-rc.2 (Hardening & Production Closure)

**Date:** 2026-08-12
**Branch:** `feat/stage-4-enterprise-ai-growth-integrations`
**Type:** Release candidate — hardening pass over the Stage-4 feature set. **Code-only:
no new database migrations** over rc.1 + Stage-4.
**Supersedes:** `v1.0.0-rc.1`

---

## 1. Summary

rc.2 closes out the Stage-4 enterprise / AI / growth / integrations programme (see
`STAGE_4_REPORT.md`) with a focused security, reliability and correctness hardening
pass. Every change in this candidate is a fix to a **confirmed** defect found during a
read-only red-team/audit — no new product features, no redesigns. Larger performance and
infrastructure items surfaced by the audit are documented as known limitations (§6)
rather than rushed in.

## 2. Confirmed fixes in this candidate

| Area | Defect | Fix | Regression guard |
|------|--------|-----|------------------|
| API auth | Scoped developer keys were valid on the whole first-party API | `EnforceApiTokenScope` confines non-`*` tokens to `/developer/*` (+ key mgmt) → `403 TOKEN_SCOPE_FORBIDDEN` | `DeveloperScopeEnforcementTest` |
| Webhooks | SSRF via numeric/hex/octal & IPv4-mapped-IPv6 hosts; redirect-to-internal | Reject numeric-host literals, decode mapped IPv6, `withoutRedirecting()` on delivery | `WebhookUrlGuardTest` |
| Identity | `mfa/disable` unthrottled | `throttle:identity-otp-verify` | (covered by route middleware) |
| Commerce | Coupon expiry/deactivation not re-checked at checkout (revenue leak) | Re-validate active/window/exhaustion under the row lock | `CartCheckoutTest` surface |
| Marketing | Drip could double-send a step across a crash | In-flight `Sending` claim before provider call | `DripCampaignTest` |
| Search | Orphaned embeddings never purged | Purge non-indexable rows in `rebuildAll` + daily `search:backfill` | `IngestionService` tests |
| Learning | `continue learning` rail unbounded | Order by recency, cap 24 | — |
| Config | Dead production media guard; no fake-notification guard | Read `media.ingestion.default`; reject fake mail/SMS/push | `ProductionConfigValidatorTest` |

## 3. Verification (run in your environment)

Gate commands are consolidated in the closure message accompanying this release. In
summary, from `apps/api`: `composer pint -- --test`, `composer analyse`, `composer
deptrac`, `composer test`; from `apps/web`: `pnpm typecheck`, `pnpm lint`, `pnpm test`,
`pnpm build`. rc.2 must reproduce the rc.1 green baseline plus the new guard tests.

## 4. Deployment

No schema migrations are introduced by rc.2. Deploy is a code roll-forward:

1. Deploy the new build (API + web).
2. `php artisan config:validate` **must exit 0** — it now enforces the real media
   provider key and rejects fake notification transports. Set `MEDIA_INGESTION_PROVIDER`
   and `NOTIFICATIONS_MAIL/SMS/PUSH_PROVIDER` to real providers (or set the explicit
   `*_ALLOW_FAKE` escape hatches only for a deliberate non-delivery environment).
3. Confirm the scheduler runs `search:backfill` (daily) — it converges the semantic
   index and is safe to run repeatedly (`onOneServer`, `withoutOverlapping`).
4. No cache/queue drain required beyond the standard `config:cache` / `route:cache`
   refresh.

## 5. Rollback

Because rc.2 adds no migrations, rollback is a straight redeploy of the previous build
(the Stage-4 rc.1-line artifact). No `migrate:rollback` is required. If only the token
-scope middleware needs to be disabled in an emergency, it is a single append in
`bootstrap/app.php` and can be reverted in isolation without touching data.

## 6. Known limitations carried forward (NOT fixed in rc.2 — by design)

These were identified by the audit as improvements, not release-blocking defects, and are
deferred to avoid destabilising the closure:

- **Search:** trigram/`pg_trgm` index for lexical fallback is not yet added; large-corpus
  lexical search remains sequential.
- **Webhook SSRF:** DNS-rebinding is mitigated by re-checking at delivery time, but IPs
  are not pinned between resolve and connect (no connect-time IP pin).
- **AI quota:** per-org quota accounting is not fully atomic under high concurrency.

## 7. External / operator-environment items — NOT claimed as passing

The following cannot be executed in the build assistant's sandbox and are **not** asserted
green here. They require the operator's environment or live credentials and must be run
before promoting rc.2 to GA:

- **Container image scan (Trivy)** — Docker build + `trivy image` on the release images.
- **Browser E2E (Playwright)** and **accessibility (axe)** runs against a live web build.
- **Storybook** visual/interaction checks.
- **Backup & restore (DR) drill** — a real `pg_dump`/restore round-trip against a staging DB.
- **Live-provider smoke** — Stripe, Mux/media ingestion, ESP/SMS, SSO IdP, and the
  embeddings provider each need real credentials to smoke-test end-to-end.

## 8. Release actions still gated

No `git push`, no image publish, and **no release tag** are performed by this candidate.
Tagging `v1.0.0-rc.2` awaits explicit authorization after the §3 gate evidence and the §7
operator checks are on record.
